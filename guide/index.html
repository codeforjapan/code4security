      03毎週、自動で点検し続ける

      試験運用中動かしてみた感想や、うまく動かなかったことを Issue で教えてください。

      危ないのは、いま触っているリポジトリより、動いたまま誰も見なくなったリポジトリです。そこで、アカウントや organization のリポジトリをまとめて毎週調べ、見つかった指摘を非公開のリポジトリの Issue にまとめる GitHub Action「weekly-security-checker」を用意しました。同じ指摘は二重に立たず、直ると自動で閉じます。

      調べるのは、依存パッケージの脆弱性、漏れたキー（コミット履歴も含む）、ワークフローの危ない書き方、そしてそれらを見つける機能が無効になっていないかです。

      使い方

      1. Issue を集める非公開のリポジトリを作ります。Issue に脆弱性の情報が載るためです
      2. 読み取り専用の fine-grained トークンを作り、そのリポジトリに SCAN_TOKEN として登録します。必要な権限は README にあります
      3. 次のファイルを .github/workflows/ に置きます

      ほかに、自動化に使えるもの

      • OpenSSF Allstar

        org の設定違反（ブランチ保護がない、外部コラボレーターがいる、危ないワークフローなど）を見つけて Issue を立てる GitHub App です。

      • Renovate

        依存の更新 PR を自動で出します。minimumReleaseAge で、公開されたばかりの版を避けられます。

      • claude-code-security-review

        PR ごとに Claude がセキュリティの観点でレビューし、問題のある行にコメントを付けます。API の料金がかかります。外部からの PR に使うときは、実行に承認を必須にしておきます。

      AIAI に相談する

      選んだものと、点検表の進み具合をまとめた相談文を作ります。ChatGPT や Claude などの AI に貼り付け、プロジェクトの説明を書き足してください。次に何をすればよいかを、AI と一緒に考えられます。

      キーやパスワード、利用者の個人情報は貼り付けないでください。AI の答えは間違っていることもあるので、コマンドは公式のドキュメントで確かめてから使ってください。

      点検するときに大事なこと
      
    
      見出しをタップすると説明が開きます。
      
    
      
      
      
        
      脆弱性は非公開の場所で扱う
      
        
      公開リポジトリの Issue に脆弱性を書くと、直す前に攻撃の手順を公開することになります。Security Advisory の下書きか、非公開のリポジトリで扱います。漏れたキーの値はどこにも貼りません。
      
      
      
      
      
        
      放置されたプロジェクトほど危ない
      
        
      動いたまま誰も見なくなったリポジトリには、古い依存パッケージや消し忘れたキーが残っていても、気づく人がいません。1 つずつではなく、アカウントや organization のリポジトリをまとめて見るようにします。
      
      
      
      
      
        
      スキャンより先に棚卸し
      
        
      把握していないものは守れません。リポジトリだけでなく、デプロイ先、ドメイン、外部連携、そしてそれぞれのアカウントの持ち主まで書き出します。
      
      
      
      
      
        
      事故はツールが見ない場所で起きる
      
        
      スキャナーが得意なのは依存パッケージとコードです。実際の漏えいは、データベースのルールや共有設定、抜けた人の権限など、ツールの外で起きることが多くあります。
      
      
      
      
      
        
      通知が多すぎると誰も見なくなる
      
        
      アラートを全部 Issue にすると、すぐ 100 件を超えることもあります。原因ごとにまとめ、動いているもの、外から触れるものを先に直します。
      
      
      
      
      
        
      直せるものは PR で、使わないものはアーカイブ
      
        
      Issue を読んで手で直すより、自動で届く修正 PR をマージするほうが速く片付きます。もう使っていないリポジトリは、アーカイブすれば直す対象から外せます（残っているキーは先に失効させます）。
      
      
      
      
      
        
      点検する仕組みそのものを守る
      
        
      全リポジトリを読めるトークンは、攻撃者にとっても魅力的です。権限は読み取りだけにして、期限を付けます。調べる対象のコードは実行しません。AI に調べさせるなら、リポジトリ内の文章に操られる前提で、書き込み権限を渡しません。
